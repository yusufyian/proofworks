# D. 结算与对账自动化（含e-CNY对接）详细方案设计

## 一、方案概述

### 1.1 业务目标
- 实现多门店、多平台、多支付渠道的自动对账
- 支持数字人民币（e-CNY）对公支付与清分
- 实现T+0/T+1差异自动处理与闭环
- 提供可审计的资金流与业务流匹配记录

### 1.2 核心价值
- **效率提升**：人工对账从数天缩短至分钟级
- **准确性提升**：自动化匹配，差错率<0.01%
- **资金安全**：实时监控异常交易，防止资损
- **合规可审计**：所有对账记录上链存证

### 3.2 自动对账匹配流程

```mermaid
sequenceDiagram
    participant 定时任务
    participant 匹配引擎
    participant 规则库
    participant 数据仓库
    participant 区块链
    participant 差异工单
    
    定时任务->>匹配引擎: 1. 触发对账任务
    Note over 定时任务,匹配引擎: 每日T+1、每小时实时对账
    
    匹配引擎->>数据仓库: 2. 查询待对账数据
    Note over 匹配引擎,数据仓库: 业务流水 vs 支付流水
    
    数据仓库-->>匹配引擎: 3. 返回数据集
    
    匹配引擎->>规则库: 4. 加载匹配规则
    规则库-->>匹配引擎: 5. 返回规则配置
    
    loop 逐条匹配
        匹配引擎->>匹配引擎: 6. 一级匹配（订单号完全匹配）
        
        alt 匹配成功
            匹配引擎->>匹配引擎: 7a. 金额校验
            
            alt 金额一致
                匹配引擎->>区块链: 8a. 标记已匹配并存证
                匹配引擎->>数据仓库: 8b. 更新状态→已对平
            else 金额不一致
                匹配引擎->>差异工单: 8c. 创建差异工单（长款/短款）
            end
            
        else 匹配失败
            匹配引擎->>匹配引擎: 7b. 二级匹配（金额+时间窗口）
            
            alt 模糊匹配成功
                匹配引擎->>差异工单: 8d. 创建待人工确认工单
            else 仍无法匹配
                匹配引擎->>差异工单: 8e. 创建差异工单（挂账）
            end
        end
    end
    
    匹配引擎->>匹配引擎: 9. 生成对账报表
    匹配引擎->>区块链: 10. 对账结果哈希上链
    
    匹配引擎-->>定时任务: 11. 返回对账结果
    Note over 匹配引擎,定时任务: 总笔数、对平笔数、差异笔数
```

**匹配规则优先级：**

| 优先级 | 匹配规则 | 匹配字段 | 适用场景 |
|-------|---------|---------|---------|
| 1 | 精确匹配 | 订单号 + 金额 + 时间(±5秒) | 标准交易 |
| 2 | 订单号匹配 | 订单号 + 金额差异<0.1元 | 手续费差异 |
| 3 | 金额时间匹配 | 金额 + 时间窗口(±30分钟) | 订单号映射错误 |
| 4 | 批次匹配 | 门店 + 金额汇总 | 批量结算 |
| 5 | 人工介入 | 无自动匹配 | 特殊情况 |

```mermaid
    Note over 收银系统,e-CNY网关: 订单号、金额、商户号
    
    e-CNY网关->>运营机构: 3. 提交支付请求
    Note over e-CNY网关,运营机构: 工行/建行/招行等
    
    消费者->>运营机构: 4. 扫码确认支付

    Note over 运营机构,e-CNY网关: 支付流水号、时间戳、状态
    
    e-CNY网关-->>收银系统: 7. 异步回调通知
    
    收银系统->>对账系统: 8. 推送支付成功记录
    
    运营机构->>e-CNY网关: 9. T+1推送对账文件
    Note over 运营机构,e-CNY网关: CSV/XML格式
    
    e-CNY网关->>对账系统: 10. 解析对账文件
    
    对账系统->>对账系统: 11. 自动匹配
    
    对账系统->>区块链: 12. 匹配结果上链
    Note over 对账系统,区块链: 订单号、金额、流水号、匹配状态
    
    对账系统->>对账系统: 13. 生成对账报表
```

**e-CNY特殊处理：**
1. **零手续费**：不扣除交易手续费（与传统支付不同）
2. **实时到账**：T+0即时入账，无需等待清算
3. **可编程性**：支持智能合约定时/条件支付
4. **双离线支付**：需特殊对账逻辑（延迟上传）

### 3.4 差异处理与闭环流程

```mermaid
sequenceDiagram
    participant 差异工单
    participant 规则引擎
    participant 人工审核
    participant 上游系统
    participant 区块链
    participant 财务系统
    
    差异工单->>规则引擎: 1. 差异类型判断
    
    alt 类型1: 长款（支付有记录，业务无记录）
        规则引擎->>上游系统: 2a. 查询原始订单
        
        alt 订单存在
            上游系统-->>规则引擎: 3a. 返回订单数据
            规则引擎->>规则引擎: 4a. 补录业务流水
            规则引擎->>区块链: 5a. 记录补录操作
            规则引擎->>差异工单: 6a. 自动关闭工单
        else 订单不存在
            规则引擎->>人工审核: 3b. 推送人工处理
            人工审核->>人工审核: 4b. 调查原因
            
            alt 确认为多收款
                人工审核->>财务系统: 5b. 发起退款
                财务系统->>区块链: 6b. 记录退款
            else 确认为系统遗漏
                人工审核->>上游系统: 5c. 补录订单
                上游系统->>区块链: 6c. 记录补录
            end
            
            人工审核->>差异工单: 7b. 关闭工单
        end
        
    else 类型2: 短款（业务有记录，支付无记录）
        规则引擎->>上游系统: 2b. 查询支付状态
        
        alt 支付中/待支付
            上游系统-->>规则引擎: 3c. 返回未完成状态
            规则引擎->>差异工单: 4c. 标记待跟进（T+3自动关闭）
        else 支付失败
            规则引擎->>财务系统: 3d. 订单核销
            财务系统->>区块链: 4d. 记录核销
            规则引擎->>差异工单: 5d. 关闭工单
        else 支付成功但未推送
            规则引擎->>上游系统: 3e. 触发补推
            上游系统->>区块链: 4e. 记录补推
            规则引擎->>差异工单: 5e. 重新匹配
        end
        
    else 类型3: 金额差异
        规则引擎->>规则引擎: 2c. 差额分析
        
        alt 差额 = 手续费
            规则引擎->>财务系统: 3f. 自动调账
            财务系统->>区块链: 4f. 记录调账
            规则引擎->>差异工单: 5f. 关闭工单
        else 差额 > 阈值（如10元）
            规则引擎->>人工审核: 3g. 推送人工复核
            人工审核->>差异工单: 4g. 标记处理结果
        end
    end
    
    差异工单->>区块链: 8. 记录完整处理过程
```

**差异处理SLA：**
- 小额差异（≤10元）：T+1 自动处理
- 中额差异（10-1000元）：T+2 人工处理
- 大额差异（>1000元）：T+0 立即告警

### 4.2 清分引擎模块

**应用场景：**
- 平台型企业：订单金额拆分（平台佣金 + 商户货款）
- 连锁门店：总部 vs 门店分成
- 联营商户：商场扣点后清分

**清分流程：**

```
原始订单金额: 1000元
    ↓
清分规则计算:
├─ 平台服务费: 1000 × 5% = 50元
├─ 支付手续费: 1000 × 0.6% = 6元
├─ 商户货款: 1000 - 50 - 6 = 944元
    ↓
生成清分指令:
├─ 账户A(平台): +50元
├─ 账户B(支付渠道): +6元
├─ 账户C(商户): +944元
    ↓
e-CNY智能合约执行:
  - 原子性转账
  - 失败自动回滚
  - 全程上链存证
```

**清分规则DSL：**
```javascript
{
  "ruleId": "RULE-001",

  "condition": "order.category == '商品' && order.amount > 0",

      "account": "platform",

      "description": "平台服务费"
    },

      "account": "merchant",

    }

  "settlement_cycle": "T+1"
}
```
